# Revisão independente das telas atuais

Escopo: fontes canônicas FreeMix somente leitura, sem abrir Native, iniciar mídia ou tocar operador/pacotes/Git. BASELINE.json registra11 fontes lidas e as duas propostas. Os scripts e patches são drafts próprios, não aplicados. As provas do candidato050500 permanecem intactas.

## Defeitos reproduzidos

1. SRT HDR, painel/remoto/srt-hdr-ui.js:11: command() não fornece prazo a fetch. Se o servidor aceitar a conexão e não concluir o corpo JSON, busy permanece true, Conferir motor e ações ficam bloqueados e polling não reconcilia. Ensaio próprio com servidor HTTP real local devolvendo headers e JSON parcial reproduziu bloqueio por mais de5s. O draft acrescenta AbortSignal.timeout(5000) nas duas chamadas, cobrindo também response.json pelo contrato de fetch. Após5s busy é liberado, Start continua bloqueado por needsCheck, sem retry. Somente GET manual/poll bem sucedido reconcilia; abort não desfaz um comando já aceito pelo motor. Reconciliar nunca significa reenviar Start automaticamente.

2. Calls, painel/remoto/calls.js:96–105: renderGuests() preserva o DOM apenas enquanto foco está num INPUT/SELECT. Alterar retorno, sair do campo sem clicar Salvar retorno e receber novos diagnósticos recria cartões com o estado salvo. Reprodução VM com a fonte exata: vídeo own-cam voltou para program, sem write. Draft guarda os valores do formulário em Map por guest.key real e mantém a edição durante polling/blur. Save recusado mantém rascunho; Save confirmado, mudança de preset e remoção do UUID limpam o rascunho. Mesmo nome com UUID novo não herda dados. A Map não guarda URL/link/credencial. Não foi criado novo botão ou modelo de configuração persistente.

3. No mesmo cartão Calls, entrada de vídeo salva removida não aparece nas options; o navegador escolhe Programa e Salvar retorno pode substituir a rota por esse fallback válido. Draft conserva option desabilitada do UUID ausente e recusa Save até escolha explícita de fonte disponível. O backend já valida fontes e mic privado; o defeito era o formulário enviar um fallback permitido em lugar do UUID ausente.

result.json contém8 casos focados PASS: as três reproduções (dois testes Calls e um HDR), quatro contratos corretivos Calls e um HDR. Os testes não usam Native nem CEF. O ensaio HDR tem HTTP real próprio com corpo parcial; todo comando de motor continua simulado. Os dois JS drafts passaram node --check. Nenhuma prova de mídia/hardware foi repetida.

## Fluxos e contratos conferidos sem nova matriz

SRT SDR: Externo → SRT / RIST → escolha uma Saída existente ou configurar livre → Destino → Conteúdo e áudio → Conferir e iniciar. Caller usa IP real do receptor e porta igual à escuta;0.0.0.0 só serve para Listener. Salvar sem iniciar guarda; Iniciar este destino envia somente o slot escolhido. Preparar SRT único ou duas portas prepara rascunho. Master é o mix do Programa; vídeo de Entrada própria não seleciona automaticamente seu áudio. O guia aponta barramento independente público com M/A/B desligados. Alpha exige recomposição;4:4:4 não é alpha/HDR universal.

HDR: Externo/SRT → SRT HDR · vídeo sem transparência → Envio para editar → IP/porta/Fonte HDR/Áudio → Verificar → Salvar → Iniciar envio HDR. Manual PQ/HEVC Main10 opaco, independente da mesa SDR. Configuração válida não comprova receptor ou encoder funcional. GET/poll não configura nem inicia. busy/dirty/needsCheck e UUID ausente bloqueiam ações; sender não muda enquanto há rascunho. A prova anterior Native24/API/UI permanece separada destes drafts.

MultiStream: Transmitir → MultiStream → saída livre/existente → Destino/Conteúdo e áudio/Conferir e iniciar. RTMP/RTMPS/HLS ficam neste contexto; SRT/RIST ficam em Externo. Quatro destinos adicionais compartilham slots: destino ocupado de outro contexto não é sobrescrito. O slot e o rascunho são guardados por contexto; transação save/configure/start captura index antes do await e bloqueia mudança. Vaga passa a Programa/H.264/1280x720 apenas após clique explícito. Transmissão principal tem acesso separado por perfil salvo. saidas.html inclui somente a apresentação guiada atual; o script antigo saidas-srt-simples-ui.js não é carregado, portanto não há essa duplicação ativa.

Calls: Configurar microfone → Usar este microfone dedicado ou Criar com dispositivo padrão → Preparar retornos → Quem deve ouvir você? / Destino do talkback → Segure para falar. Selecione explicitamente Todos os Calls ou Somente os selecionados; a seleção salva também vale para a mesa. Abrir/poll não envia comando de talkback. Release/blur/pagehide/visibilidade fecham lease, Native watchdog oferece limite independente. Mic privado fica mute/monitorNONE/tracks desligadas e envio individual usa PCM privado; roteiro backend recusa mic do diretor como fonte comum de retorno. O convidado vê/ouve são resumo do estado salvo; editar requer Salvar retorno. Programa e retorno individual de imagem têm capacidades distintas (entrada própria até5fps JPEG), sem nova homologação aqui.

As novas telas Calls/HDR não disparam GO/Cut/delete ao abrir ou polling. Saídas tem comandos Mix Cut/Take explícitos, não ligados a navegação; revisão não repete ou substitui a matriz de operações canônicas já comprovada. Backend, leases, áudio privado e hardware não foram alterados. Antes de integrar os drafts, Root deve conferir baselines; eventual aplicação requer versão/prova posterior ao candidato050500. Os patches usam nomes baseline/draft para revisão, não um git apply cego no produto.

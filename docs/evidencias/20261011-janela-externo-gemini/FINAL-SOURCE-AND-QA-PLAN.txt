## PARTE 1: Revisão Final de Coerência de Código (Source-Only Review)

### 1. Diagnóstico Estrutural e de Contratos

1. **Guards de Concorrência e Bloqueio (`busy`):**
   - **Tabs de Saídas (`#nums`):** Em `draw()`, cada botão numérico recebe `b.disabled = busy;`. No evento `E('nums').onclick`, há a trava de guarda defensiva:
     ```javascript
     if (busy || !b || b.disabled) return;
     ```
   - **Tabela de Status (`#status-rows`):** No evento `E('status-rows').onclick`, a seleção de linha do gerenciador verifica rigorosamente:
     ```javascript
     if (busy || !tr) return;
     ```
   - **Controles de Disparo e Ação:** Todos os botões executores (`#start-one`, `#start-all`, `#virtual-toggle`, `#fs-program`, `#fs-preview`, `#fs-multiview`, `#fs-open-input`, `#save-close`, `#advanced-btn`) têm `disabled = busy` garantido durante chamadas em trânsito dentro da rotina `run()`.

2. **Fidelidade aos Contratos de Rede (`outputs_network`):**
   - A função `toggleOutput` adere estritamente aos comandos canônicos `start` e `stop`:
     - Ao iniciar: emite `action: 'outputs_network'`, `command: 'start'`, `senderId`, `protocol`, `name`, `groups`, `mode`, `input`, `audioTrack`, `audioSourceUuid`, `alpha`, `fillKey`, `keyName` e `precisionBits`. Nenhum comando fictício `configure` é inventado.
     - Ao parar: emite `action: 'outputs_network'`, `command: 'stop'`, `senderId` e `protocol`.
   - Limpeza atômica do rascunho local (`drafts.delete(keyOf(proto, slot))` e `persistDrafts()`) executada imediatamente após a confirmação do início da transmissão.

3. **Persistência de Rascunhos em `sessionStorage`:**
   - Chave isolada por origem: `'freemix.outputs.drafts:' + location.host`.
   - Sanitização na carga com validação regex `/^(NDI|OMT):[0-3]$/`.
   - `save-close` aciona `persistDrafts()` antes de fechar/notificar a janela mãe.

4. **Preservação de Seleção e Memoização (`fill`):**
   - A função `fill(el, html)` compara `el._html !== html` antes de sobrescrever o `innerHTML`. Se as opções forem idênticas no ciclo de polling de 2000ms (`refresh()`), o DOM não sofre mutação e dropdowns abertos não são fechados.

5. **Startup Silencioso (Zero Mutating Commands):**
   - Na inicialização (`start()`), o código executa exclusivamente leituras paralelas `GET /api/settings` e `GET /api/outputs` via `Promise.all`. Zero requisições `POST /api/control` são emitidas no carregamento da janela.

### 1. Parâmetros e Isolamento de Ambiente

- **Escopo do Recibo:** `MOCK_API_REAL_DOM_ONLY`
- **Ambiente de Teste:** Executável padrão do Microsoft Edge em modo headless (`--headless=new`, `--window-size=700,540`), conectado via CDP WebSocket nativo (Node.js 24).
- **Isolamento de Processos e Dados:**
  - Servidor HTTP Loopback exclusivo em porta efêmera (`127.0.0.1:0`).
  - Diretório de perfil Edge temporário isolado em pasta própria (`FreeMix-QA-Profile-Externo-*`), preservado para auditoria (zero chamadas `fs.rm` recursivas).
  - Isolamento de Saída: Todos os artefatos de evidência gravados com prefixo `externo_` (ex: `externo_gate0_startup_r1.png`, `receipt-test-externo-dom-r1.json`), **garantindo que nenhum arquivo de Calls R3/R4 seja sobrescrito**.

### 2. Contrato da Mock API Sintética

O servidor loopback interceptará e responderá sem acionar processos nativos de OBS/NDI:

| Rota / Endpoint | Método | Resposta Mockada | Efeito no Estado Sintético |
| :--- | :--- | :--- | :--- |
| `/api/settings` | `GET` | `{ success: true, settings: { virtualCamera: false } }` | Retorna status da câmera virtual e periféricos |
| `/api/outputs` | `GET` | `{ success: true, outputs: { ndi: { available: true, senders: [] }, omt: { available: true, senders: [] }, audioSources: [] } }` | Retorna capacidades de envio NDI e OMT |
| `/api/control` (`outputs_network`) | `POST` | `{ success: true }` (suporta delay configurável) | Altera o estado `active` / `outputActive` do sender especificado |
| `/api/control` (`settings_virtual`) | `POST` | `{ success: true }` | Alterna flag `settings.virtualCamera` |
| `/api/control` (`settings_projector`) | `POST` | `{ success: true }` | Confirma solicitação de tela cheia |

### 4. Regras Estritas de Implementação do Runner (R1)

- **Encapsulamento Léxico:** Toda invocação de `ev()` multiline será estritamente protegida por IIFE:
  ```javascript
  await ev(`(() => {
    // Código de teste isolado sem poluição do escopo global V8
  })()`);
  ```
- **Rastreabilidade de PINs:** Hashes dos arquivos `externo.html`, `externo.js` e `vmix-dialogo.css` validados no startup e reconferidos no bloco `finally`.
- **Limitação de Escopo Declarada:** O runner incluirá declaração explícita no recibo de que testes de áudio WASAPI real, dispositivos físicos, drivers de captura NDI e tráfego WAN não foram executados nem inferidos.
